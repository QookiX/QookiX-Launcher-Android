# 架构决策记录（ADR）

这个目录记的是**为什么这么做**，不是「怎么做的」。代码里能看出来的东西不要写进来；
写的是当时的约束、被否掉的备选方案、以及后来可能推翻它的条件。

必要性：项目长期是单人维护（bus factor = 1），
半年后的自己、或者第一个外部贡献者，最缺的就是这些「当时到底在想什么」。

## 新增一份 ADR

1. 复制下面的模板，文件名 `NNNN-短横线标题.md`（编号递增，不复用）
2. 在 `README.md` 的表格里加一行
3. 不要改动已采纳的 ADR；要改就写一份新的，并在旧的「状态」里标 **已被 NNNN 取代**

```markdown
# NNNN. 标题

- 状态：提议中 / 已采纳（YYYY-MM-DD） / 已被 NNNN 取代
- 背景：当时遇到什么问题，有哪些硬约束（人力、时间、上游限制）

## 决定

一句话说清做了什么。

## 备选方案与否决理由

- 方案 A：为什么不要

## 后果

- 好了什么
- 付出了什么（这是重点，别只写好处）
- 什么条件下应该重新考虑
```
